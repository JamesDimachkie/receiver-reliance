# F-WP3-001 — target pointer-budget reachability was not acceptance-pinned

Status: **RESOLVED in proposal wording; fresh-context cycle 2 returned
NO-NEW-EVIDENCE.**

The first WP3 refuter found that the compact 4095/4096/4097 pointer fixtures
exercised only the common phase. The mixed target-4097 case deliberately had a
common error, so target validation was unreachable; an implementation could
omit the reached-target pointer pre-pass without failing an explicit fixture.

Correction: `continuation-specs/GEN_0_5_SEMANTICS.md` now requires a valid
enabled tuple, a verified digest-pinned registry, an empty common/selector
pool, and target-only additional-property pointers of exactly 4095, 4096, and
4097 scalars after RFC 6901 escaping. The first two pin the exact
`ERR_SCHEMA`/80 pointers; the third pins sole root `ERR_LIMIT`/90. Request ID,
JCS+LF response, receipt, empty stderr, exit, no partial pool, and zero engine
invocation are all fixture obligations.

Regression check: the cycle-2 refuter independently verified that the fixed
16-scalar `/decision_input/` prefix plus keys of 4079/4080/4081 `A` scalars
produces exactly 4095/4096/4097-scalar target pointers.
