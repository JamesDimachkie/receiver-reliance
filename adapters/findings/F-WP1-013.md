# F-WP1-013 — Scope digests used a non-injective newline join

Source: Deep Security Scan intake 10 (2026-08-12), finding
`csf_5f7b1451b3f0e17bb08d15f6` (high).

Both adapter surfaces digested path sets as
`sha256("\n".join(sorted(items)))`. The serialization is not injective: the
single item `"a\nb"` and the two items `"a", "b"` produce identical
digests, so `declared_scope_sha256` could equal `recorded_use_scope_sha256`
for materially different path sets and a scope expansion crafted around
embedded newlines could hide from the equality predicate.

Repair: `portable_preflight._scope_hash` and `reference_host._scope_hash`
now digest the canonical JSON array of the sorted items — injective for
every representable path set — and a cross-surface agreement test pins the
two implementations to one law. The historical newline join survives only
in the committed `proof/arm_b1.py` experiment arm, whose receipts are
sealed history and whose two arms shared one derivation (the scheme cannot
change a recorded outcome). The truth fixtures carry labels only, so no
fixture regeneration was required; the WP1 outcome receipt was regenerated
and its counts are byte-identical (0 false holds, 18/18 detection).
Regression: `FailClosedBoundaryTests.test_scope_digest_is_injective_across_newline_items`,
`ScopeDigestAgreementTests.test_scope_digest_matches_portable_and_is_injective`.
