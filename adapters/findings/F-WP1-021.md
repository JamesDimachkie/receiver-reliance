# F-WP1-021 — Portable preflight transport was not binary end to end

Source: Deep Security Scan findings `csf_f260bc51ff2949adde392590` (medium) and
`csf_431f37cb4acc97b8ab85c429` (low).

The portable CLI passed locale-configured text standard streams to preflight.
That reintroduced host-dependent decoding after the adapter's byte boundary;
a surrogate-bearing text row could also raise during byte measurement. Output
used the host text encoding and newline rules.

Repair: both portable CLI and standalone adapter standard-stream/file paths now
pass binary streams through `process_jsonl`. The processor accepts binary or
text compatibility sources and sinks, decodes each byte row strictly as UTF-8,
contains a surrogate encode failure per line, and emits explicitly UTF-8 JSONL
bytes with LF. Regression:
`TransportDecodeTests.test_surrogate_text_is_rejected_and_binary_output_stays_utf8`
and `PortableCliHardeningTests.test_all_runtime_modes_load_declared_repository_bytes`.
