# F-WP1-011 — Duplicate JSONL members collapsed last-value-wins

Source: Deep Security Scan intake 10 (2026-08-12), finding
`csf_048c221833a3d6e63e8825a1` (high).

The JSONL boundary parsed rows with plain `json.loads`, so duplicate object
members silently collapsed to the final occurrence before any validation
ran. Contradictory duplicate `record`, `family`, `record_id`, or evidence
members could reduce to an ordinary value and classify READY, while
`native_evidence_sha256` sealed only the already-collapsed object — the
supplied ambiguity was unrecoverable from the result. A strict producer or
first-wins consumer could interpret the same bytes differently. The
grounded batch transport already rejected duplicates, so this was also an
API/CLI parity gap against the repository's own declared parser boundary
(`portable/THREAT_MODEL.md` boundary 1).

Repair: the JSONL boundary now parses with a duplicate-rejecting
`object_pairs_hook`; a duplicate member at any depth is a deterministic
per-line `REJECTED_INVALID`. Line acquisition is bounded before allocation
(a newline-free flood buffers at most `MAX_JSONL_BYTES` characters), and
parser resource errors (`RecursionError` included) become deterministic
line results instead of process crashes.
Regression: `FailClosedBoundaryTests.test_duplicate_object_members_are_rejected_not_last_wins`,
`test_nested_duplicate_members_are_rejected`,
`test_parser_resource_errors_become_deterministic_line_results`,
`test_newline_free_flood_is_bounded_and_rejected`.
