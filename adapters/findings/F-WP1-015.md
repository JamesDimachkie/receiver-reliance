# F-WP1-015 — Ordinary scope globs crossed path segments

Source: Deep Security Scan finding `csf_c64015672838bf3310dc7f5a` (low).

`_in_scope` used `fnmatchcase` on a complete repository-relative path. Python
filename matching does not treat `/` as a boundary, so `src/*.py` also matched
`src/admin/key.py`. That could suppress an outside-scope observation while
preserving an apparently equal declared/recorded digest.

Repair: scope matching is still case-sensitive and host-independent, but it is
now segment-aware. `*`, `?`, and character classes operate within one `/`
segment; an entire `**` segment is the only recursive wildcard. Paths remain
opaque strings and no filesystem or host separator normalization is applied.
Regression:
`FailClosedBoundaryTests.test_scope_globs_are_case_sensitive_and_segment_bounded`.
