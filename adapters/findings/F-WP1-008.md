# F-WP1-008 — Transcript validation was not total over non-finite JSON

Historical general-adapter finding. F-WP1-009 later stood the transcript and
runner surface down; the portable fallback has no runner dependency.

Status: repaired in code.

Python's default JSON decoder accepts `NaN` and infinities. The earlier
transcript validator then passed those values to canonicalization or exact
re-execution paths that could raise uncaught exceptions.

Repair: transcript JSON uses an explicit `parse_constant` rejection, bounded
base64 input, guarded canonicalization, and guarded core re-execution. NaN,
positive/negative infinity, malformed retained decision input, and engine
exceptions now return deterministic H5 issues. Re-execution uses an isolated
accepted-core process, so an in-process module-cache substitution cannot spoof
semantic validation. Regression:
`Finding008TranscriptTotalityTests`.
