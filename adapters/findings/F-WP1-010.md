# F-WP1-010 — Empty evidence stream exited as success

Source: Deep Security Scan intake 10 (2026-08-12), findings
`csf_9e86e5fae76792ca7c754b26` (high) and the same-path truncation limb.

`process_jsonl` initialized its non-ready counter to zero, skipped blank
lines, and returned 0 when no row was emitted, so an empty or blank-only
required host-evidence stream exited as success. A caller gating on the
documented exit status could not distinguish "all records READY" from "no
evidence supplied". The CLI additionally opened `--output` for writing
before reading `--input`, so passing one path for both truncated the
evidence before any row was read and reached the same success path.

Repair: a stream with zero rows now emits one `PREFLIGHT_STREAM_EMPTY`
diagnostic row with status `INSUFFICIENT_EVIDENCE` and exits 2, and the CLI
refuses identical resolved input/output paths before opening either.
Regression: `FailClosedBoundaryTests.test_empty_or_blank_stream_is_insufficient_not_success`,
`test_cli_refuses_identical_input_and_output`.
