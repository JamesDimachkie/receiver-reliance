# F-WP1-012 — Abstention could shadow detection; profile checks skipped on non-READY paths

Source: Deep Security Scan intake 10 (2026-08-12), findings
`csf_6f35c3d2731af848eec8bdd4` (high), `csf_0501a903df0d70f565f635aa`,
`csf_54055ed338518688c885e4d0` (mediums).

Three related control-layer gaps:

1. **Ordering.** `preflight` returned `INSUFFICIENT_EVIDENCE` for envelope
   issues before running any later control layer, so a record that was both
   insufficient on one layer and detectably contradictory on another was
   reported as an abstention — detection downgraded to abstention, against
   the lane's own taxonomy law.
2. **Unchecked profiles reported as checked.** `_profile_issues` ran only on
   the fully-READY path, while `profile_checked` was set to "a profile was
   supplied" on every early return, so non-READY results claimed a
   validation that never ran. A malformed or contradictory supplied profile
   was silently ignored.
3. **Loose comparisons and domain.** Profile fact comparison used Python
   `==`, so `True` compared equal to `1`; and integers outside the governed
   engine's safe-integer domain (|n| > 9007199254740991) passed the
   bounded-JSON walk.

Repair: every control layer that can run does run, issues accumulate, and
status precedence is `REJECTED_INVALID` over `INSUFFICIENT_EVIDENCE` over
`READY`. `_profile_issues` validates supplied profiles on every non-None
envelope path (skipping only the two comparisons that need assessor facts),
`profile_checked` is true exactly when validation ran, fact comparison is
type-strict, and the JSON domain walk enforces the engine's safe-integer
bounds. The all-408 outcome replay is byte-identical under the new order
(0 false holds, 18/18 detection — no corpus row's class changed).
Regression: `FailClosedBoundaryTests.test_precedence_rejected_dominates_insufficient`,
`test_profile_checked_reflects_actual_validation`,
`test_type_strict_equality_distinguishes_bool_from_int`,
`test_out_of_domain_integers_are_domain_violations`.
