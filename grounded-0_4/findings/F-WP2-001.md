# F-WP2-001 — dual-use predicate fields were under-classified

Status: **RESOLVED locally.** Disposition: **ADDRESSABLE-ADDITIVE**. This was
an authority-legibility defect in the 0.4 register and lint, not a change in
accepted engine classification behavior. No accepted implementation, fixture,
or receipt byte is implicated.

## Minimized witness

OBL-02 uses the same required fact path in separate atomic predicates:

```json
{"op":"ABSENT","path":"/facts/exact_reference"}
{"op":"EQ","path":"/facts/exact_reference","value":"LATEST"}
```

The prior collector accumulated `/facts/exact_reference` into both a global
reference set and a presence set, then computed semantic references as set
subtraction. The presence use therefore erased the independent `EQ` value
use. The launch register labeled the field `presence_only`, and the launch
lint accepted that label.

The same per-atomic traversal reproduced exactly 30 affected entries:

- OBL-02: `exact_reference`
- OBL-03: `declared_scope_sha256`, `recorded_use_scope_sha256`
- OBL-04: `provenance_record_sha256`, `provenance_subject_id`
- OBL-05: `assessed_claim_version_sha256`, `evidence_claim_version_sha256`
- OBL-07: `authorization_decision`, `authorization_record_sha256`
- OBL-08: `manifest_effect_sha256`, `requested_effect_sha256`
- OBL-12: `sender_id`
- OBL-13: `validation_result`
- OBL-18: `last_authority_arrival_sequence`
- OBL-19: `invocation_sha256`
- OBL-20: `authorized_effect_sha256`, `invoked_effect_sha256`,
  `observed_effect_sha256`
- OBL-26: `effect_sha256`, `execution_receipt_effect_sha256`,
  `invocation_nonce`, `revoked_at`
- OBL-28: `action_manifest_bytes_base64`,
  `executed_effect_bytes_base64`, `trusted_render_bytes_base64`
- OBL-29: `affordable_covering_query_id`, `asked_addressee_id`,
  `asked_query_cost`, `asked_query_id`, `asked_query_target_fact_id`

## Impact

The programmatic query and generated table exactly reflected the register, but
the register understated classification authority for those 30 fields. A
caller could reasonably infer that changing one of their values could not
affect classification even though a value-comparing predicate consumes it.
The engine itself already evaluated those predicates correctly.

## Correction

`lint_contract.collect_refs` now assigns each pointer use according to its
own atomic predicate. Presence and value-use sets remain independent; any
value use makes a field semantic, while `presence_only` is accepted only for
exclusive presence use. The 30 register entries and rationales are corrected
to `semantic` / `referenced by a value-comparing predicate`, and the public
table is regenerated.

The authority census changed from `semantic=111`, `presence_only=64`,
`inert_disclosed=10`, `inert_registered_debt=14` to `semantic=141`,
`presence_only=34`, `inert_disclosed=10`, `inert_registered_debt=14`.
The corrected register raw SHA-256 is
`C3414FC751C3B5ECA43A4932C694641D801A21F2CF53C42BE3A8C87C234CF499`.
