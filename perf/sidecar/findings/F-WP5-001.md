# F-WP5-001 — executed-input custody was incomplete

## Finding

The first receipts pinned a hand-maintained source list. Python could import a
repository `.pyc`, or code/data could open an unlisted transitive repository
file, without making the receipt fail. The profiler also claimed exact
single-pass work counts from an unbound earlier command.

## Correction

Receipt generation now re-executes before repository imports under `-B` and a
unique, existing, empty temporary `-X pycache_prefix`. A Python audit hook
records repository regular-file reads throughout the traced Python process
tree. The receipt declares every unique traced path and pins each raw SHA-256;
`verify_receipts.py` requires exact traced-set/pin-set equality and rejects
repository `.pyc` inputs. The profile itself reruns the 1,142-check equivalence
oracle and binds 93/124 reduced fixtures and 116 saved atomic calls.

The coverage is deliberately narrow: Python `open` audit events for repository
regular files in the traced Python process tree. It is not OS-wide I/O
provenance and does not observe native or non-Python child reads.

## Regression evidence

Profile attempt 5 records 22 pinned repository inputs, 5,072 read events, 501
trace files, and 500 completed child trace records. Every recorded bytecode
cache was empty at start and end. The manifest is explicitly limited to Python
`open` audit events for repository regular files; it is not native or OS-wide
I/O provenance. Verifier result: 122 checks, zero failures.
