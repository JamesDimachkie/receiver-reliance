# F-WP5-007 — Valid early responses were spuriously rejected; the timeout probe raced child cold start

Source: independent diagnosis during intake 10 (2026-08-12), confirming
scan finding `csf_294a53041e57b3d16a0ff054` (both halves) and root-causing
the one observed suite failure (`counted-timeout-child-accepted-once`).

**Implementation defect (the serious half).** The stdout reader poisoned
the stream whenever a complete frame arrived while the phase was still
`WRITING`. With unbuffered pipes every request byte is in flight the moment
`write_all` returns, but the phase flipped to `AWAITING_RESPONSE` only
after two further lock acquisitions — so a fast, fully correct child could
answer inside that gap and be killed for it ("sidecar emitted output before
host frame write and flush completion"). Reproduced deterministically with
a blocking-write stream, and observed once as an uncaught crash in nine
full suite runs. Repair: the reader now waits — bounded by the caller's own
`timeout_seconds` — for the writer's lock-protected transition, then
applies the unchanged correlation checks. Identity comes from the envelope
digest, never from phase timing (consistent with F-WP5-002's law and its
disclosed limit that digest correlation does not prove consumption). A
child that emits early and then stops draining leaves the writer blocked;
the bounded wait expires, poisons, and the termination unblocks the writer,
so liveness is preserved. Regression: `supervisor:midwrite-valid-*` — a
correct correlated frame emitted mid-write (4 KiB chunks over a 1 MiB
request) must be admitted with zero protocol failures.

**Test defect (the observed flake).** The stall probe charged the child's
entire interpreter cold start (~0.25 s measured) against a fixed 0.5 s
request deadline. Idle boxes passed; under process-creation churn — which
the suite itself generates — the deadline fired before the child could read
the request and write its acceptance marker (12/12 failures under a
40-spawner churn probe; CPU saturation alone did not trip it). Repair: the
stall adversary now signals readiness after interpreter start and the
harness polls that signal on a generous bound before issuing the short
request; the marker check carries its observed bytes as detail; and the
receipt's `child_accepted_requests` records the measured marker length
instead of a hardcoded `1` — recording a constant where an observation
belongs is the defect class F-WP5-005 closed, and it had survived here.

**Stderr capture correction (F-WP5-004 erratum).** The dedicated stderr
reader returned after its first 64 KiB chunk, so F-WP5-004's claim that it
"captures every stderr byte" was false for longer streams (probe: 65,536
of 5,242,880 bytes captured, digest over the prefix only, undisclosed).
The reader now drains every byte, retains a bounded 1 MiB evidence buffer,
and `stderr_evidence()` reports `total_bytes`, `retained_bytes`, and
`sha256_scope` so a truncated digest can never present as complete.

Suite after repair: `checks=728 failures=0`. Both admitted receipts were
regenerated (the grounded 0.4.1 governance increment had already changed
pinned sources under them; see the chronology in `COST_MODEL.md`).
