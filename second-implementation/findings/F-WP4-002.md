# F-WP4-002 — coverage steering omitted the reference dispatch target

Status: fixed in author repair after fresh refuter attempt 1. Severity: HIGH.
Official author strike: 1.

## Evidence

The original campaign enumerated only non-underscore callables when installing
local `sys.monitoring` events. Consequently it did not monitor the frozen
reference `_execute` entry point or its private decision helpers, so the
reported edge set could not support the promised steering claim.

## Repair

The underscore exclusion was removed. All callable code objects within the
black-box reference target are eligible for local branch events. Receipts now
list both monitored and actually observed code-object names, require
`_execute`, and set campaign status to `FAIL` unless `_execute` generated an
observed branch event. A deterministic 20-identity smoke observed `_execute`
and the private parse/schema/dispatch/classification helpers.

No source text, bytecode disassembly, or code-object contents are inspected;
the names and opaque branch edges exist only to bind the black-box coverage
receipt.
