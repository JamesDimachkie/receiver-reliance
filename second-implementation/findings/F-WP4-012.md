# F-WP4-012 — artifact receipt paths remained active after invalidation and the author receipt was unsealed

Status: fixed with an explicit residual in hardening wave W4. Deep-scan
findings `csf_5f722bc110a52a38c0679d1b` and
`csf_d4f457ad95e04355476c81d8`.

## Evidence

The verifier recorded a candidate path-set mismatch but still joined and read
every receipt-controlled path. The same verifier treated the mutable author
receipt as the source of both candidate-file and subordinate-receipt hashes,
without an independently supplied digest for the author receipt itself.

## Repair and residual

Candidate rows must now be a closed, duplicate-free set of well-formed path
and digest objects exactly equal to the compiled allowlist. Any mismatch stops
all candidate filesystem access; only allowlisted paths can be opened. Receipt
and authority reads are regular-file and size bounded.

`verify_artifacts.py --author-receipt-sha256 <SHA256>` supplies an external
trust anchor and fails on a mismatch. The no-argument compatibility command
continues to verify self-consistency but reports
`UNSEALED_SELF_CONSISTENCY_ONLY` in its result. That mode does not authenticate
the mutable author receipt and must not be represented as doing so; a caller
seeking authenticity must bind and supply the digest from a separate trusted
channel.
