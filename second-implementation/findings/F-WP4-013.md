# F-WP4-013 — framing-class parity divergence found by the first house-scale sweep; resolved by the bounded precedence law

Status: RESOLVED — corrected 2026-08-16 after the rebind review round 2
refuted this finding's original reproduction. This document supersedes the
earlier text in full.

## What actually happened

1. A custodian regeneration mis-invocation executed the first house-scale
   coverage sweep ever run (50,000 identities requested; execution stopped
   after 1,050 identities at the first divergence, per the campaign's
   halt-on-divergence behavior and the receipt's `executed_identities`
   field; the campaign gate had been
   DEFERRED, so only 20-identity smokes existed). It recorded exactly one
   divergence, at identity 1049, on a framing-class input (bytes recorded
   in the sweep receipt; candidate stdout SHA-256
   `BAA52EC96ED84A513C18D3FFCB10BC8B4A7E3B5D8FF8C3061B06708178629EAA`).
   That sweep ran against the candidate BEFORE the round-2 scanner
   precedence fix.
2. The round-2 hardening fix (bounded structural-precedence law in
   `rr2.py`'s post-limit scanner: container matching, root membership,
   trailing-data validity, and LF framing proven before schema-vs-limit
   precedence, with frozen-parity fallback) addressed exactly the
   input class the divergence sat in.
3. Supporting evidence on the fixed candidate, stated to exactly what each
   record binds: (a) a subsequent executing coverage-campaign run with the
   same recorded seed completed 1,500/1,500 identities with
   `divergence_count: 0`, status PASS (aggregate receipt retained in the
   rebind planning record; the receipt does not itself bind a candidate
   hash or per-identity rows); (b) the original receipt-bound 295-byte
   divergence input replays byte-identically on the present candidate and
   the properly invoked frozen runner (`ERR_JSON`, stdout SHA-256
   `9543AAFCF326CEE49F67E5106EC886B82BD9176C3E1D5946C4994CFCA9A567C2`),
   independently reproduced by the rebind review round 4.

## Retraction

The earlier version of this finding claimed a PRE-EXISTING three-engine
divergence with the frozen reference returning `ERR_INTERNAL`/exit 3. The
rebind review round 2 demonstrated that claim arose from a mis-invocation
of the frozen runner (missing its required `execute` argument) and from
mixing LF-framed and unframed inputs across engines; with consistent
framing, the frozen reference and both candidate generations agree on the
described document in both LF states. That reproduction is retracted.

## Methodology lessons (bound into the campaign law)

- The campaign corpus grows from coverage feedback during execution, so
  identity inputs are path-dependent: only an EXECUTING replay reproduces
  a sweep's sequence; generation-only replays do not.
- Any future divergence claim must bind the exact raw bytes, LF state,
  interpreter, invocation form, exit codes, and stdout hashes for every
  engine, produced by the harness's own invocation paths.
