# F-WP4-009 — wrapper execution sealed success before validating the outer request

Status: fixed in this author hardening patch; post-application suite execution
required. Severity: HIGH. Deep-scan finding
`csf_99b169a9402543b529bffc96`.

## Evidence

`execute_wrapper` previously read only `semantic_request` and
`configuration`. Deleting the outer `request_id` still produced `ok:true`;
the response identity was silently derived from the embedded semantic
request. Valid but mismatched outer request IDs or operations could likewise
reach semantic execution, and malformed configuration, attention-card,
budget, pause, or clarification fields were not adjudicated as a complete
wrapper request before response construction.

## Cause and repair

Wrapper schema and binding checks existed only in the after-the-fact
transcript evaluator. The execution entry point did not share that control.

The repair adds `validate_wrapper_request` as the common pre-execution gate.
It first bounds already-materialized values, then applies the closed composed
wrapper request schema, the semantic envelope bindings, the outer-to-inner
request-ID and operation bindings, the registry-derived obligation binding,
and the configuration-specific attention-card seal. The closed schema owns
configuration, attention-card shape, budget range, pause state, clarification
state, required members, and extra-member rejection.

`execute_wrapper` calls the control before serializing or executing the
semantic request. Validation failure returns a sealed deterministic wrapper
error and cannot construct `ok:true`. Successful responses copy outer routing
fields only after the control passes. `validate_wrapper_binding` invokes the
same request control, preventing drift between execution and transcript
admission.

The focused gate removes the semantic executor while exercising missing and
mismatched identities and operations, invalid configuration, invalid budget,
pause and clarification states, extra members, and a tampered attention-card
seal. Every case must return a schema-valid, self-sealed wrapper error with
the expected pointer; any attempted semantic execution makes the regression
fail.
